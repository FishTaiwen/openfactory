# 架構

[English](../en/architecture.md) | [繁體中文](architecture.md)

先使用一個 Repository，內部明確區分模組職責。模組化不必一開始就拆成多個 Repository 或微服務。程式語言、資料庫與部署方式尚未選定。

| 元件 | 職責 |
|---|---|
| Core | 帳號、權限、主檔參照、稽核紀錄規則 |
| Receiving | 收料紀錄與收料明細批次 |
| IQC | 檢驗任務、檢驗計畫版本快照、證據、品質判定 |
| Connectors | 外部識別碼映射與資料交換 |

單獨使用的模組須提供或隨附最低限度的帳號與主檔能力，不應要求安裝全部模組。整合時透過公開資料契約，避免直接讀寫另一模組的資料庫。

收料模組負責收料事實，IQC 負責檢驗結果。既有 ERP 可作為供應商、料號與採購單主檔的權威來源，介接器負責映射，避免產生兩套互相衝突的主檔。

品質放行與實際庫存異動分開記錄。PASS 代表可辦理入庫，倉庫確認後才記錄實際入庫；HOLD 禁止放行。部分允收須明確記錄各處置數量。

目前尚未實作 SAP 或 MES 介接器，實際整合需確認產品、版本、介面、權限與現場欄位對應。
