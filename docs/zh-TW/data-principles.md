# 資料原則

[English](../en/data-principles.md) | [繁體中文](data-principles.md)

1. 使用固定內部 ID，並以「來源系統＋外部收料 ID＋明細 ID＋批次 ID」建立唯一外部識別。
2. 數量須有單位並精確保存小數；不同單位未經核准換算不得合併。
3. 收料事實、檢驗判定、處置核准與倉庫異動分別記錄。
4. 開始檢驗時保存圖面版次、檢驗計畫版次與抽樣依據快照，後續改版不可默默覆蓋歷史證據。
5. 修改須留下操作者、時間、原因、資料版本與修改前後值；更正須可追溯。
6. 重複匯入或 API 重送不得新增重複收料或檢驗任務；內容衝突須提示。
7. 拆批與部分處置保留母批關聯；允收、待處置及拒收數量須與對應批次總量一致，抽樣數另行記錄。
8. 權限由伺服器檢查，具有檢驗權限不代表具有特採核准權限。
9. 公開 Repository 僅使用虛構範例資料。
